// 01 — The Problem

Manual audits don't scale.

In enterprise and service provider networks, verifying security configurations across dozens of devices is slow, error-prone, and inconsistent. One misconfigured device is all it takes.

⏱

Time-consuming audits

Manual SSH into each device, running show commands, comparing output against a policy document — repeated for every device, every audit cycle.

⚠️

Human error

Engineers miss things. A Telnet-enabled VTY line or an HTTP server left on is easy to overlook when checking 40 devices manually.

📋

No audit trail

Manual checks leave no structured record. When compliance is questioned, there's no evidence of what was checked, when, and what the result was.

🔁

Not repeatable

Different engineers check different things in different ways. There's no guarantee the same policy is applied consistently across all devices.

// 02 — How It Works

Gather. Assert. Report.

The checker uses Ansible's native IOS resource modules to pull structured configuration state directly from devices — no screen scraping, no TextFSM parsing.

01

Inventory Definition

Devices are grouped in a YAML inventory file (routers, switches). Credentials are injected via Ansible Vault — no plaintext passwords in the repo.

02

State Gathering

Resource modules like ios_vlans, ios_interfaces, and ios_ntp_global are run with state: gathered to pull live config as structured data.

03

Compliance Assertions

Each gathered fact is evaluated against policy using Ansible assert tasks with ignore_errors: true — so the playbook runs to completion and reports all violations, not just the first one.

04

Results

Pass/fail output per device per check. Violations are clearly flagged with the assert failure message identifying exactly what the issue is.

check_ssh.yml 
---
- name: Gather VTY line config
  cisco.ios.ios_command:
    commands:
      - show run | section line vty
  register: vty_output

- name: Assert SSH only (no Telnet)
  ansible.builtin.assert:
    that:
      - "'transport input all' not in
         vty_output.stdout[0]"
      - "'transport input telnet' not in
         vty_output.stdout[0]"
    fail_msg: FAIL — Telnet enabled on VTY
    success_msg: PASS — SSH only
  ignore_errors: true

// 06 — Conclusion

What this demonstrates

This project goes beyond basic automation — it treats network configuration as structured state that can be queried, asserted, and reported on systematically. The same approach scales to hundreds of devices with zero additional manual effort.

Using Ansible's native resource modules with state: gathered — instead of parsing raw CLI output — means the compliance logic is clean, readable, and maintainable. Every check is a testable assertion. Every failure is a clearly identified policy deviation. This is how network compliance should work at scale.
